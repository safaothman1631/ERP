# Kurdish ERP — Marketing Site

Public, trilingual marketing site for the Kurdish ERP (`zoho-kurdish.iq`).

Built with **Astro v4** (static), Tailwind, MDX content collections. Deployed to Vercel at the apex domain. Trilingual from day one: Kurdish Sorani (default), Arabic, English — all with full RTL support.

This is a **separate codebase** from the application at `app.zoho-kurdish.iq`. It shares brand tokens via `@zoho-kurdish/tokens` (TODO: extract to a workspace package once the app design system is published).

## Quick start

```bash
cd marketing
npm install --legacy-peer-deps
npm run dev    # http://localhost:4321
npm run build  # → dist/
npm run preview
```

## Locales

| Code | Language | URL prefix     | RTL |
|------|----------|----------------|-----|
| `ku` | Kurdish Sorani (default) | `/` (root) | yes |
| `en` | English | `/en/` | no  |
| `ar` | Arabic  | `/ar/` | yes |

Every page emits `<link rel="alternate" hreflang="...">` for the three locales plus `x-default`.

## SEO & structured data

- Sitemap auto-generated by `@astrojs/sitemap` (incl. locale variants and hreflang).
- `robots.txt` at `public/robots.txt`.
- JSON-LD `Organization`, `SoftwareApplication`, `FAQPage`, `BlogPosting` emitted per page via `<StructuredData>`.
- OG images at `public/brand/og/` (placeholders — designer to provide).

## Analytics

Wrapped in `<AnalyticsScripts>`, gated by env vars:

- `PUBLIC_PLAUSIBLE_DOMAIN` — self-hosted Plausible domain (preferred).
- `PUBLIC_PLAUSIBLE_SRC` — Plausible script URL (defaults to `https://plausible.io/js/script.js`).
- `PUBLIC_GA4_ID` — Google Analytics 4 measurement ID (fallback / compatibility).

If neither is set, no scripts are emitted. Cookie consent (R1.14) is enforced before non-essential scripts execute.

### Plausible: self-hosted vs hosted?

Per design ADR-G-G (Marketing Analytics): we prefer **self-hosted Plausible** on a small VPS (~USD 10/mo) for full data sovereignty and to avoid the ~USD 9/mo hosted floor scaling with traffic. The trade-off is ~30 min of ops setup per quarter for upgrades. Open decision — flag for founder before launch.

## A/B testing

Minimal cookie-based A/B helper at `src/lib/ab.ts`. One sample experiment ships on the homepage hero CTA wording (`landing-hero-cta`):
- Variant A: "بەخۆڕایی تاقیبکەرەوە" (Try free)
- Variant B: "بینینی دیمۆ — ٩٠ چرکە" (See demo — 90 seconds)

Variant assignment is deterministic per visitor (cookie `_abc`), persists 30 days, and emits a `experiment_exposure` Plausible event on first render.

## Deployment

- **Production:** Vercel project `kurdish-erp-marketing`, domain `zoho-kurdish.iq` + `www.zoho-kurdish.iq`.
- **Preview:** every PR gets a Vercel preview URL (`vercel.json` configures this).
- **CI:** `.github/workflows/marketing-ci.yml` runs lint, build, Lighthouse, link-check on `marketing/**` changes.

### Required env (Vercel project settings)

| Env var | Purpose | Required? |
|--------|---------|-----------|
| `PUBLIC_SITE_URL` | Canonical origin (`https://zoho-kurdish.iq`) | yes |
| `PUBLIC_APP_URL` | App origin for login CTAs (`https://app.zoho-kurdish.iq`) | yes |
| `PUBLIC_PLAUSIBLE_DOMAIN` | e.g. `zoho-kurdish.iq` | optional |
| `PUBLIC_PLAUSIBLE_SRC` | e.g. `https://plausible.zoho-kurdish.iq/js/script.js` | optional |
| `PUBLIC_GA4_ID` | e.g. `G-XXXXXXXXXX` | optional |
| `PUBLIC_LEADS_ENDPOINT` | App endpoint for sales-lead POST (default `https://app.zoho-kurdish.iq/api/marketing/leads`) | optional |
