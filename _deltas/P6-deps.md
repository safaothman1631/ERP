# P6 — Dependencies to install

> Generated by the DevOps + Security + Mobile work delivered in P6.
> The phase agent **does not modify `package.json` / `requirements.txt`** —
> the user installs from this list at their own convenience.

## 1. Mobile (`mobile/`) — npm

Listed in `mobile/package.json`. Install with:

```bash
cd mobile
npm install
```

| Package | Version | Purpose |
|---|---|---|
| `@capacitor/core` | `^6.1.0` | Capacitor JS bridge runtime. |
| `@capacitor/cli` | `^6.1.0` | `cap` CLI (`build`, `sync`, `open android/ios`). |
| `@capacitor/android` | `^6.1.0` | Android platform shell. |
| `@capacitor/ios` | `^6.1.0` | iOS platform shell. |
| `@capacitor/splash-screen` | `^6.0.2` | Launch splash. |
| `@capacitor/status-bar` | `^6.0.1` | Native status bar styling. |
| `@capacitor/preferences` | `^6.0.2` | Persisted key-value store (default-printer id, etc.). |
| `@capacitor/filesystem` | `^6.0.1` | Native filesystem (receipt PDFs, exports). |
| `@capacitor/network` | `^6.0.2` | Connectivity-state events for POS queue. |
| `@capacitor-community/bluetooth-le` | `^7.1.0` | BLE printer (`mobile/src/bridge/printer.ts`). |
| `@capacitor-mlkit/barcode-scanning` | `^6.2.0` | ML Kit barcode (`mobile/src/bridge/scanner.ts`). |
| `rimraf` | `^5.0.5` | Cross-platform `rm -rf` for `npm run clean`. |
| `typescript` | `^5.4.5` | Already a frontend dep; pinned here for `capacitor.config.ts`. |

**Post-install steps:**

```bash
cd mobile
npm run add:android                 # scaffolds the `android/` directory
npm run add:ios                     # (macOS only) scaffolds the `ios/` directory
# These directories are committed.
npm run build:android               # produces a debug APK
```

## 2. Frontend (`frontend/`) — no new npm deps from P6

Nothing to add. The mobile bridges import from the mobile-only deps above; the
frontend keeps shipping its existing web bundle.

## 3. Backend (`backend/`) — no new pip deps from P6

`backend/app/api/csp_report.py` reuses the existing FastAPI + redis stack;
no new Python deps required.

## 4. CI runtime (GitHub Actions) — no install

`grafana/setup-k6-action@v1` installs k6 on the runner at workflow time.
`github/codeql-action/*@v3` is GitHub-hosted.
`gitleaks/gitleaks-action@v2` is GitHub-hosted.

The `pip-audit` job installs `pip-audit==2.7.3` on the runner only — it
is not in `backend/requirements.txt`, by design.

## 6. GH Secrets / Variables to create

| Name | Scope | Value |
|---|---|---|
| `LOAD_TEST_TARGET_URL` | repo secret | Staging Cloud Run base URL, e.g., `https://staging-api.erp.zoho.kurd.iq`. |
| `LOAD_TEST_USER_EMAIL` | repo secret | Email of a load-test user provisioned on staging. |
| `LOAD_TEST_USER_PASSWORD` | repo secret | The user's password. |
| `LOAD_TEST_TENANT_ID` | repo secret | Tenant id for the load-test user. |
| `CLOUDRUN_URL` | Vercel project env | The Cloud Run service URL the Vercel rewrites point at. Used by `vercel.json`. |

The Workload Identity Federation migration removes `GCP_SA_KEY` from
the repo secrets — see `docs/security/workload-identity-federation.md`
§4 for the cutover sequence.
